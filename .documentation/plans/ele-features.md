# ele configuration, reminders and recipes

## Why

Give ele a configuration a user can switch and tune from one place, reminders that surface at session start from a date or every N days, and recipes that turn a reusable procedure into a user skill and keep skills from going stale. Configuration comes first so each feature after it is switched through it.

## Context

- As of 2026-10-22: `Options` in `internal/config` declares `auto_note_writes` (default off) and `checkpoint_gate` (default on), kept in the data dir's `config.json` and read through `ele config get`
- As of 2026-10-22: note kinds are decision, fact, handoff, plan and question (`Kinds` in `internal/notes`); a dated reminder has been written as a fact note, which shows from the day it is written, not from its date, newest first within the session-start block's budget (`contextBudget` in `cmd/ele`)
- As of 2026-10-22: `~/.claude/hooks/measure-reminder.sh`, a SessionStart hook in claude-config, prints a notice when `~/.claude/cache/hook-stats.last` is missing or over 7 days old; `~/.claude/scripts/hook-firings.py`, which `/hook-stats` runs, touches that file
- As of 2026-10-22: `ele remember` refuses a note over 3 lines, and every live note loads each session, so a multi-step procedure has no home in ele

## Decisions

- One plan for all three, decided 2026-10-22 by the user: two plans are active and the plan audit flags more than three
- Configuration's structure is settled before any option is added, decided 2026-10-22 by the user, so auto note writes, nudges, recipes and reminders each land as an option in one layout
- A reminder shows from its date until closed; a nudge is a recurring reminder that comes back N days after it was last marked done, decided 2026-10-22 by the user
- ele:recipe gets both halves, decided 2026-10-22 by the user: proposing a recipe as a user skill, with the Write/Skip approval notes use, and auditing skills for stale commands and versions
- Auto note writes default to off, decided 2026-10-22 by the user: no user gets notes written without asking unless they turn it on
- A recipe always asks Write/Skip, whatever auto note writes says, decided 2026-10-22 by the user: it writes a skill under the user's skills, heavier than a note
- Auto note writes covers every proposal through ele:remember's Propose section, handoffs and supersessions included, decided 2026-10-22 by the user: one rule for the Stop hook and every skill that proposes through it
- The option is `auto_note_writes`, read by the Stop hook, whose block reason says to write and report when it is on, and by the remember skill through `ele config get`, decided 2026-10-22 by the user: neither tells the model to ask when the option is on
- A note written without asking is reported with its id and words, decided 2026-10-22 by the user, so a wrong one can be forgotten
- The hook is tested in Go and the skill by a remember eval with the option on and off, each seen red, decided 2026-10-22 by the user
- A reminder is a note of kind `reminder` with a `due: YYYY-MM-DD` key, closed by a `closed:` timestamp, decided 2026-10-22 by the user, so it shares the notes store and a nudge can add `every: N` to the same note
- A reminder is saved with `ele remember --kind reminder --due <date>`, scoped as any note, and `ele:remember` turns a spoken date into one; listed, closed and reopened with `ele reminder list [--all]|close|reopen`, as handoffs are, decided 2026-10-22 by the user
- A due reminder sits outside the start block's budget, as questions do, in its own section above the notes naming `ele reminder close <id>`, decided 2026-10-22 by the user: the user asked to see it, its date keeps the count small, and a dropped reminder fails silently
- A reminder shows in the startup, `/clear` and compact blocks whose local date is on or after its due date, until closed; before then it shows nowhere in the block, decided 2026-10-22 by the user
- The option is `reminders`, boolean, default on, decided 2026-10-22 by the user: a reminder shows only what the user saved. Off, none shows; saving, listing and closing still work
- A reminder whose words match an open one is refused whatever its due date, decided 2026-10-22 by the user: the same words at another date are the same reminder moved, re-dated with `--supersedes`
- A nudge may name a done file, `--done-file <path>`: its last change counts as the nudge marked done, and a missing file shows it at once, decided 2026-10-22 by the user, so `/hook-stats` marks the nudge done with `hook-firings.py` unchanged; an id written into claude-config breaks silently when the nudge is re-created, and a model told to close it cannot be tested
- Closing a nudge re-arms it: `due` becomes the close date plus N and `closed` stays empty, `ele reminder list` shows it open with its interval, and `ele forget` retires it, decided 2026-10-22 by the user
- Nudges switch with the `reminders` option, no option of their own, decided 2026-10-22 by the user: a nudge is a reminder
- A nudge is saved with `ele remember --kind reminder --every N [--due D] [--done-file P]`, `--due` defaulting to today with `--every`, decided 2026-10-22 by the user
- The hook-stats nudge is one `--global` nudge per owner running `measure-reminder.sh` today, personal and hyve, each naming `~/.claude/cache/hook-stats.last`, handed to the user as commands with the hook's removal from both profiles' settings, decided 2026-10-22 by the user
- `ele reminder`'s usage names `ele remember --kind reminder` for saving one, decided 2026-10-22 by the user: the user looked for it under `ele reminder`
