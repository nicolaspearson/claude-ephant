# Move checkpoint and ticket-audit into ele

## Why

ele already depends on checkpoint and ticket-audit, and they depend on ele, but the two sides sit in different repositories, so nothing tests the coupling. Moving them into ele's plugin lets the hooks, scripts, skills and agent type ship and version together, gives `claude plugin eval` a plugin to run against, ends with one language, and leaves a repo anyone can install: nothing in it depends on claude-config, `~/.agents` or this user's own files. The design is the spec's "Into ele" section, moved here from `~/.agents` in phase 1.

## Context

- As of 2026-10-17 the skills are in `~/.agents/skills/checkpoint` and `~/.agents/skills/ticket-audit`, the agent is `~/.claude/agents/checkpoint-reviewer.md`, the hooks are `checkpoint-review.sh` and `checkpoint-snapshot.sh`, registered in `~/.claude/settings.json`, and `/ticket-claims` and `/checkpoint-stats` are `check-ticket-claims.py` and `checkpoint-stats.py` under `~/.claude/scripts/`
- As of 2026-10-17 ele's plugin holds `plugin/hooks/hooks.json` and the skills handoff, mine, plan, recall and remember
- As of 2026-10-21 `HOMEBREW_TAP_TOKEN` is valid for one year, to about 2027-10-21; after that Release's Tap job fails at the tap checkout, once the release is already published
- As of 2026-10-17 `claude plugin eval` refuses runs that grant Bash while `~/.docker` holds Docker Desktop's symlinks, and every ele skill except mine needs Bash

Phase 1 stays a pure move; the shareable item after it removes what ties the plugin to this user
- The gate's off switch is a `userConfig` boolean, `checkpoint_gate`, default true, decided 2026-10-20: Claude Code has no way to turn off one hook of a plugin, and an option shows in `/config` where an env var would not. - The prerequisites live in the spec's "Into ele" section until the README item takes them, decided 2026-10-20
- The README installs the binary with `go install`, decided 2026-10-20, its place in the install order set by the Homebrew decision below: no clone and no Task for a user, and the binary is pure Go (`modernc.org/sqlite`). The clone and `task install` route is for contributors. The README item ticks only once someone without access to this user's GitHub account installs from it, since as of 2026-10-20 the repository is private and every install step fails for anyone else
- The ports are grouped subcommands, decided 2026-10-20 by the user: `ele checkpoint density|log|stats` and `ele ticket claims|corpus|ledger`, as `plan`, `owner` and `handoff` are; `reviewGate` gains `ele checkpoint` beside `checkpoint-`, which history still needs. Checkpoint's three go first, log leading, since it runs at every checkpoint and is the one tied to the Bash state path; then claims, ledger, corpus
- Release binaries, decided 2026-10-21 by the user and amended the same day from a pushed `v*` tag to release-please: every push to main runs CI's check, then release-please opens or updates a release PR from the conventional commits; its merge creates a draft release with its tag, and when that release's commit is the one the run checked, one job cross-compiles macOS and Linux for amd64 and arm64 with `CGO_ENABLED=0` and uploads tarballs and a `checksums.txt` to it with `gh release upload --clobber`, then publishes it as latest. No GoReleaser, so no new tool to pin; no Windows, since the plugin's hooks are Bash. Tarball names carry no version, so `releases/latest/download/<name>` is a stable URL for the README. The check runs first because a release PR opened with `GITHUB_TOKEN` triggers no checks; the repository must allow Actions to create pull requests
- Homebrew and an install script, decided 2026-10-21 by the user, replacing that day's earlier release-first, `go install` second order: the README installs with `brew install nicolaspearson/tap/ele` first, `curl … install.sh | sh` second and `go install …@latest` third, and the four-line release download goes. The formula is a binary one, the release tarball per OS and arch with its sum from `checksums.txt` and a `test do` running `ele version`: no Go needed and it covers Linuxbrew. `.github/workflows/tap.yml` renders and pushes it to `nicolaspearson/homebrew-tap`, called by Release after publishing and runnable by hand with a tag, then installs that tag with `install.sh` on macOS and Linux and with `brew` on macOS, failing unless `ele version` prints the tag. It pushes with `HOMEBREW_TAP_TOKEN`, a fine-grained token on that repository's contents alone; the tap repository and the token are the user's to make. `install.sh` is POSIX `sh` with `curl` only, no `gh`: latest or `ELE_VERSION`'s tag, checked against `checksums.txt`, into `${ELE_INSTALL_DIR:-~/.local/bin}`, warning rather than failing when that is not on `PATH`. `task upgrade` keeps its PATH and version checks and installs through `install.sh`, so the download and check live once; `task lint` runs `shellcheck` on it
- The rest of the design is in the spec's "Into ele" section: what stays in claude-config, the data paths kept, and the contract the port keeps
